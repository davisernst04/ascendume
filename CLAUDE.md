- `MICROSOFT_CLIENT_ID` / `MICROSOFT_CLIENT_SECRET` — Entra app registered for "personal Microsoft accounts and any organizational directory" (tenant `common`)

## Known Constraints & Gotchas

### Vercel Blob
- The blob store is configured as **private** — always use `access: 'private'`, never `'public'`
- Always pass `addRandomSuffix: true` to avoid conflicts when the same filename is uploaded more than once
- `BLOB_READ_WRITE_TOKEN` must be set or the upload step is skipped (the parse route handles this gracefully — `originalFileUrl` is nullable)

### OpenAI Structured Output (`generateText` + `Output.object`)
- OpenAI's `response_format` structured output requires **every field** in `properties` to appear in `required`
- Never use `.default(...)` on Zod fields passed to `Output.object` — it makes them optional and removes them from `required`, causing a schema validation error
- Always use plain `.string()`, `.boolean()`, `.array(...)` etc. with no defaults in schemas passed to `Output.object`
- `generateObject` is deprecated in AI SDK 7 — use `generateText({ output: Output.object({ schema }) })` and read `result.output`

### PDF Parsing (`pdfjs-dist`, `lib/pdf-text.ts`)
- Uses the `legacy` build on the server, with the worker imported statically and run on the main thread (`globalThis.pdfjsWorker`)
- Keep `pdfjs-dist` on the same version `react-pdf` depends on, so only one copy is installed
- Don't go back to `pdf2json`: it drops the positioning gaps LaTeX PDFs use instead of space glyphs, so words run together

### AI SDK Versions
- `ai` v7 + `@ai-sdk/openai` v4 are in use (Node 22+ required)

### Pinned Below Latest (on purpose)
- **TypeScript stays on 6.0.x**: `typescript-eslint` (pulled in by `eslint-config-next`) only supports `typescript <6.1`. Revisit TS 7 when it widens its peer range.
- **ESLint stays on 9**: `eslint-plugin-react`, `eslint-plugin-import` and `eslint-plugin-jsx-a11y` (bundled in `eslint-config-next`) don't declare ESLint 10 support yet.
- **`@types/node` stays on 24**: it matches the Node 24 LTS runtime, not the local Node.

### react-pdf v11
- Suspense mode is on by default in v11; `LatexPdfPreview` passes `suspense={false}` to keep its own loading/error UI.

### LaTeX Live Preview (SwiftLaTeX)
The live PDF preview compiles LaTeX in the browser using SwiftLaTeX (pdfTeX compiled to WASM).

**Engine chain:** `LatexPdfPreview` (React) → `/latex-worker.js` (Web Worker) → `/PdfTeXEngine.js` → `/swiftlatexpdftex.js` (inner Worker) → `/swiftlatexpdftex.wasm`

**Rendering:** After compilation, `components/latex-pdf-preview.tsx` renders the resulting PDF using `react-pdf` (`Document` + `Page` components with `renderTextLayer={false}` and `renderAnnotationLayer={false}`) — raw canvas output, no browser PDF viewer chrome.

**TeX Live bundle** is served as static files from `public/texlive/pdftex/` with one subdirectory per kpse format number:
- `3/` — TFM font metrics (requested **without** extension — kpse format 3 implies `.tfm`)
- `10/` — Format file: `swiftlatexpdftex.fmt` (14 MB, pre-compiled by the WASM itself)
- `11/` — Font maps: `pdftex.map`
- `26/` — LaTeX packages/classes/configs (`.sty`, `.cls`, `.def`, `.cfg`, `.tex`)
- `32/` — Type1 fonts (`.pfb`, requested **with** extension)

**Critical gotchas:**
- The format file (`pdftex/10/swiftlatexpdftex.fmt`) **must** be generated by `scripts/generate-swiftlatex-fmt.mjs` using the actual `swiftlatexpdftex.wasm`. A format compiled by a different pdfTeX binary will fail with "Fatal format file error; I'm stymied" due to mismatched dump magic numbers.
- `swiftlatexpdftex.js` uses synchronous XHR to fetch TeX files. The `fileid` response header is used as the in-WASM filename; since Next.js static file server doesn't set this header, `swiftlatexpdftex.js` has been patched to fall back to extracting the filename from the URL path.
- For `\input{name}` without extension (e.g. `\input{glyphtounicode}`), pdfTeX passes the bare name to kpse. `swiftlatexpdftex.js` has been patched to retry with `.tex` appended when format 26 returns a non-200. Additionally, `glyphtounicode` (no extension) is served alongside `glyphtounicode.tex`.
- Never copy a format file from a local TeX Live install into `public/texlive/` — a locally compiled pdflatex format is incompatible with the WASM.

**Regenerating the format file** (only needed if `swiftlatexpdftex.wasm` changes):
```bash
node scripts/generate-swiftlatex-fmt.mjs
# Outputs: public/texlive/pdftex/10/swiftlatexpdftex.fmt (~14 MB)
```

## Architecture

**Ascendume** is an AI-powered resume builder. Users create/edit resumes, get AI-enhanced bullet points, and export to PDF.

### Route Structure

The `app/` directory uses two route groups plus standalone routes:

- `app/(marketing)/` — Landing page (unauthenticated)
- `app/(application)/` — Dashboard (authenticated); page components live here as `-page.tsx` files rather than in `page.tsx` directly
- `app/(application)/[id]/` — Resume builder for an existing resume (URL: `/<id>`)
- `app/(application)/new/` — Resume builder for a new resume (URL: `/new`)
- `app/(application)/layout.tsx` — Every app page renders inside `AppFrame` (`components/app-header.tsx`): a header with the account menu for signed-in users, or sign-in/sign-up prompts for guests. The resume list lives on the signed-in home (`app/(application)/dashboard-page.tsx`), not a sidebar. `/new` works for guests; `/[id]` redirects guests to sign-in itself
- Guest drafts live in `localStorage` (`lib/resume-draft.ts`). When a signed-in user opens `/new` with a draft present, the first autosave creates the resume in their account and clears the draft — that is how work carries over after sign-up or sign-in
- Auth pages take `?next=<path>` (validated by `lib/safe-redirect.ts`) to return users where they were
- `app/auth/sign-in/` and `app/auth/sign-up/` — Auth pages
- `app/api/` — Route handlers:
  - `resumes/` — list and create resumes
  - `resumes/[id]/` — get, update (delete-and-recreate for list sections), delete
  - `resumes/parse/` — parse an uploaded PDF (≤ 5 MB, must contain text) into a new resume
  - `review/` — the LLM judgment pass of the review (session required)
  - `ai/rewrite/` — the shared rewrite engine: `add-number` (one bullet + the user's answer) and `draft` (interview answers → bullets). Returns proposals only; the client shows a diff to accept or reject
  - `events/` — first-party analytics counts; accepts only the fixed events in `lib/analytics/events.ts`
  - `auth/[...all]/` — better-auth catch-all handler (also serves account deletion)

PDF export has no server route: the builder downloads the PDF that `LatexPdfPreview` already compiled in the browser.

### Data Layer

- Schema: `lib/db/schema.ts` — tables: `user`, `session`, `account`, `verification` (better-auth managed), `resumes`, `personalInfo`, `workExperience`, `education`, `skillCategories`, `projects`, `certifications`
- Skills are categories the user names (`Label: items` rows in Jake's template), one `skill_categories` row each. `lib/skill-categories.ts` holds the defaults and converts the legacy `{ technical, frameworks, tools }` shape still found in old browser drafts
- DB client: `lib/db/index.ts` using Neon serverless driver
- Auth: `lib/auth.ts` (server), `lib/auth-client.ts` (client)

### Resume State

`lib/resume-context.tsx` provides a React context (`ResumeContext`) with the full resume data shape (`ResumeData`) used throughout the builder. The builder page reads/writes through this context, which syncs to the DB via `lib/use-resume-persistence.ts`.

### Review

The rubric is data in `lib/review/rubric.ts` (id, category, kind, scope, reason). Deterministic criteria run in the browser (`lib/review/deterministic.ts`) for guests too; LLM criteria run in `app/api/review/route.ts`, which drops any finding that isn't for an LLM-kind criterion or doesn't cite a real bullet id (`lib/review/llm.ts`). Bullet ids are `<section>:<entryId>:<index>` from `lib/review/bullets.ts`, computed the same way on both sides.

`lib/review/use-review.ts` holds review state in the builder. A review runs only when asked (button, or `/<id>?review=1` after an upload from `/review`). It waits for `LatexPdfPreview` to report a compile of the current source so the one-page check uses a real page count, and marks itself outdated after any edit — it never re-runs on its own. The preview stays mounted while the review tab is shown for that reason.

### AI rules (no fabrication, caps)

- The AI never invents a claim, number or metric. `lib/ai/rewrite.ts` checks every output with `inventedNumbers` (`lib/ai/fabrication.ts`), retries once, then refuses. Keep that check on any new generation path.
- Every AI route requires a session and takes a daily use from `lib/ai/usage.ts` (`ai_usage` table, per user and UTC day): 3 reviews, 30 rewrites, 5 imports. Uses are refunded when the AI call fails.
- Models: `reviewModel` (stronger, scoring), `rewriteModel` and `parseModel` (`gpt-6-luna`, cheapest) in `lib/ai/models.ts`.

### Privacy, deletion, analytics

- `app/privacy/page.tsx` is the plain-English privacy note. **Update it whenever you change what is stored, what goes to OpenAI, or which third parties load.** It is a promise to users, not boilerplate.
- Account deletion uses better-auth's `deleteUser` (`lib/auth.ts`). Rows cascade from `user`; uploaded PDFs are deleted from Blob first via `lib/blob-files.ts`. Any new user-owned table needs `onDelete: "cascade"` to `user`, and any new file storage needs cleanup there.
- Analytics: `track()` from `lib/analytics/track.ts` sends to Vercel Analytics and to `analytics_events`. Only the six events in `lib/analytics/events.ts` exist, with enum-only props — never add a prop that could carry resume text.

### Visual design

Tokens live in `app/globals.css`: an academic, earth-toned palette. Parchment surfaces and warm ink; forest green for anything you click (`bg-brand`, Button `default`); a soft ochre highlighter for review findings, AI proposals and the "Review" action (`bg-marker`, `.highlight`, Button `marker`); oxblood for strike-throughs and errors (`danger`). Only the resume page (`.sheet`) casts a shadow. Type is Alegreya (headings, `font-display`, the wordmark) with Alegreya Sans for the interface, both self-hosted through `next/font`. Use the token colors (`ink`, `ink-soft`, `rule`, `mist`, `surface`, `raised`, `brand`, `marker`, `danger`, `ok`), not raw Tailwind palette colors.

**No scrolling to reach a form or see the page.** The builder's title and actions portal into the app header (`HEADER_SLOT_ID` in `components/app-header.tsx`) on md+ screens; the preview is sized to fit the desk's height and shows one page at a time with a pager; list sections are accordions with one entry open (`useOpenEntry` in `components/builder/fields.tsx`); field hints stay to one short line. Keep new builder UI inside that budget.

The landing page is a single screen (hero only, sized to the window height, nothing to scroll to); keep it that way. Its background is a forest-green leather cover (`.notebook-cover` in `globals.css` layers a seamless grain tile over the forest-green ground), and the resume sits straight. Its motion (letter-by-letter headline, buttons wiping in, a one-time "ATS scan" of the resume ending on a score of 100) is CSS keyframes in `globals.css` with start times passed from the components as `--at` or inline delays, so it plays once from server HTML before hydration. The highlight and section-tick positions in `components/landing/hero-resume.tsx` are percentages of `public/resume-preview.png`: re-measure them if that image changes.

The builder splits into `components/ResumeBuilder.tsx` (toolbar, section nav, the desk with page/review), `components/builder/section-editors.tsx` (one editor per section, plus the `SECTIONS` list in default order) and `components/builder/fields.tsx` (labelled fields, entry blocks, remove-with-confirm).

Each resume stores the order of its body sections (`resumes.section_order`, `lib/section-order.ts`); Contact always stays first. The section nav, the LaTeX and the review all follow it. Always pass stored or submitted orders through `normalizeSectionOrder`.

### Key Conventions

- **Server Components by default** — add `"use client"` only for interactivity/hooks
- **Absolute imports** — always use `@/components/...`, `@/lib/...` etc.
- **Named exports** everywhere except `page.tsx`, `layout.tsx`, `route.ts`
- **`cn()`** from `@/lib/utils` for conditional Tailwind classes
- **Drizzle inferred types** — use `typeof table.$inferSelect` for DB model types
- **No default exports** outside Next.js conventions
- Schema changes require both `npx drizzle-kit generate` + `npx drizzle-kit push`
- A migration that moves data (like `0001_skill_categories.sql`, which backfills before `0002` drops the old table) must have its SQL run before `push`, because `push` diffs the schema and skips hand-written backfills
